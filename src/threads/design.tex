\subsection{Synchronization}

\textbf{Q6:} Consider parent thread \texttt{P} with child thread \texttt{C}.
How do you ensure proper synchronization and avoid race conditions when
\texttt{P} calls \texttt{wait(C)} before \texttt{C} exits?  After \texttt{C}
exits?  How do you ensure that all resources are freed in each case?  How about
when \texttt{P} terminates without waiting, before \texttt{C} exits?  After
\texttt{C} exits?  Are there any special cases?

\begin{quote}
To ensure synchronization and prevent race conditions:

    P calls wait(C) before C exits → P locks C, waits on a condition variable, and releases the lock when C signals its exit.
    P calls wait(C) after C exits → P directly cleans up C’s resources after acquiring a lock.
    P terminates before wait(C), while C is running → C becomes an orphan; the kernel handles cleanup after C exits.
    P terminates after C exits → If P hasn’t waited, C’s resources are freed when P exits.

Proper locking and cleanup prevent resource leaks and race conditions.
\end{quote}

\textbf{Q7:} How are race conditions avoided when multiple threads call
\texttt{timer\_sleep()} simultaneously?

\begin{quote}
disabling interrupts during list operations. This ensures atomic updates, prevents interference, and maintains a consistent sleep list.\end{quote}

\textbf{Q8:} How are race conditions avoided when a timer interrupt occurs
during a call to \texttt{timer\_sleep()}?

\begin{quote}
Race conditions in timer_sleep() are avoided by disabling interrupts during list operations. This ensures that sleep list modifications are atomic, preventing concurrent access issues. It also guarantees a consistent state and prevents unexpected rescheduling while a thread is being added or removed.
\end{quote}


\subsection{Rationale}

\textbf{Q9:} Critique your design, pointing out advantages and disadvantages in
your design choices.

\begin{quote}
  Advantages:\\
    Prevents Race Conditions: Disabling interrupts ensures that multiple threads don’t interfere with each other.
    Good Synchronization: Using locks and condition variables avoids busy-waiting and improves CPU efficiency.
    Proper Resource Cleanup: The parent thread waits for the child and cleans up resources, preventing memory leaks.\\
Disadvantages:\\
    Too Much Locking: Frequent locks might slow down performance when many threads are active.
    Priority Issues: Lower-priority threads might be delayed if high-priority threads keep running.
    Complex Cleanup: If thread_join is not handled well, some thread resources might not be freed properly.
    
\end{quote}

\textbf{Q11:} Describe the sequence of events when a call to
\texttt{lock\_acquire()} causes a priority donation.  How is nested donation
handled?

\begin{quote}
  When a thread waits for a lock in \texttt{lock\_acquire()}, it checks if its priority is higher than the lock holder’s effective priority.  
If so, the function \texttt{set\_effective\_priority()} updates the lock holder’s priority to match the waiting thread’s priority.

To handle nested donation, \texttt{set\_effective\_priority()} recursively updates priorities through the lock-thread chain.  
If the lock holder is also waiting for another lock, the priority update continues to ensure correct donation.
\end{quote}

\textbf{Q12:} Describe the sequence of events when \texttt{lock\_release()} is
called on a lock that a higher-priority thread is waiting for.

\begin{quote}
 \begin{itemize}
    \item Remove the lock from the thread’s held locks list.
    \item Recalculate effective priority as the maximum of the thread’s original priority and remaining donations.
    \item Unblock the highest-priority waiting thread and grant it the lock.
    \item If the unblocked thread has higher priority, trigger a context switch.
\end{itemize}
\end{quote}

\textbf{Q13:} Describe a potential race in \texttt{thread\_set\_priority()} and

  \begin{itemize}
    \item A thread setting its priority may override an active priority donation.
    \item Disabling interrupts prevents race conditions by ensuring atomic updates.
    \item Using locks could cause deadlocks due to interactions with priority donation.
\end{itemize}
\end{quote}

\subsection{Rationale}

\textbf{Q14:} Why did you choose this design?  In what ways is it superior to
another design you considered?

\begin{quote}
  \begin{itemize}
    \item Maintaining sorted wait lists was complex and unnecessary.
    \item Selecting the highest-priority thread at scheduling time is simpler and faster.
    \item Sorting adds overhead (\texttt{O(n log n)}), while linear selection (\texttt{O(n)}) is more efficient.
\end{itemize}
\end{quote}
